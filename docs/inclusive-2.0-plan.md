# SeatPlanner Inclusive 2.0｜Coding Agent 改版執行計畫

> **任務類型：** 現有靜態網頁應用的 UX／品牌定位／新手導覽／品質與隱私全面改版。  
> **輸入基線：** 使用者提供的 `SeatPlanner-main.zip`；參照《第九屆教育部獎助研發特殊教育教材教具競賽簡章》、SeatPlanner 作品說明書與正式創作說明。  
> **重要：** 本檔是給 Coding Agent 逐階段實施的規格與驗收標準，**不是已完成的程式修改**。標示「已確認」的事項來自本次 ZIP 靜態檢查／既有 Node 測試；其餘屬待實作、待驗證項目。

## 0. Agent 必須先遵守的執行原則

1. **先建立 Git 分支、標記現行提交並保留原始 ZIP／可執行備份**；不得直接破壞已投稿版本。建議分支 `feature/inclusive-ux-v2`，並保存修改前可下載的完整 JSON 標準範例。
2. **優先維護資料相容性**：原有 `localStorage`、v1–v4 JSON、多班級、既有抽籤結果、手排草稿、自由教室、分組活動必須繼續運作。未經必要性證明，不得大幅推翻架構。
3. **本專案是無後端靜態站**：原生 HTML/CSS/JavaScript，`index.html` 可從本機開啟；不可強制導入伺服器、資料庫、付費 API、第三方帳號、雲端登入或外部 CDN。新增圖形應採專案內 SVG／CSS／本機靜態素材。
4. **重要操作不可默默改動或清空學生資料**。每次可能影響排位的變更，先顯示預覽／受影響人數／保留選項；需破壞性變更時要求確認並提供可復原途徑。
5. **低調而清楚地體現融合教育**：公開介面不放大障礙分類，不顯示 IEP、診斷、特殊身分、私密調整理由，也不以學生特質評分分組；相關設計應表達為「適性安排」「優先保留需要的位置」「每位學生都有參與機會」。
6. **使用者體驗以初次操作的普通班教師為準**。不用教學手冊，也應完成建班、排位、展示、備份；高階細節收在進階設定。不能只靠美化 CSS 交差。
7. **每階段需可獨立測試、提交並交付報告**。發現規格衝突，先記錄決策與原因，不要擅自刪除現有功能；驗收未過不得宣告完成。
8. **需支援繁體中文與英文**，以繁中為主要文案；手機、平板與桌機皆需可操作，鍵盤及螢幕閱讀器不應被排除。
9. **禁止新增第三方追蹤或資料外傳**。目前首頁載入外部 `site-stats.js`，參賽／離線版應移除或明確隔離，並對外連行為做測試。
10. **不得宣稱未獲證明的教學成效**。功能、案例、教師觀察、真實前後測要分開；不可編造實證、評分或無障礙合規認證。

## 1. 原始碼盤點與已確認的問題

目前 ZIP 專案的主體：

| 檔案 | 現有職責／改版重點 |
|---|---|
| `index.html` | 單頁畫面骨架、管理／展示、班級與教室設定、多模式按鈕、模態窗；新增歡迎頁／導覽主容器 |
| `assets/styles.css` | 全站視覺及響應式 CSS；整理視覺系統與簡化布局 |
| `js/app.js` | `init()`、狀態／事件／班級切換與存檔協調；處理新手觸發、使用者操作紀錄、錯誤提示 |
| `js/constants.js` | `STORAGE_KEY = classroom-seat-master:v4`、`VERSION = 4`、預設 601 班；保持相容性 |
| `js/storage.js` | localStorage 存讀、v1–v4 匯入、JSON 匯出；修正例外處理並增加首次使用 metadata |
| `js/i18n.js` | 繁中／英文介面語系；增加導覽及新 UI 字串 |
| `js/ui.js` | 設定／座位／驗證渲染；新增狀態導向提示及減少認知負荷 |
| `js/group-planner.js`、`js/group-ui.js` | 2–6 人分組、性別策略、分組操作；演算法正確性與操作可理解性 |
| `js/room-layout.js` | 自由教室、圓桌／U 型桌、座位及通道；幾何驗證與排位保留 |
| `js/manual-seating.js`、`js/seat-engine.js` | 手排、固定預排、抽籤與容量檢查；避免回歸、改進錯誤說明 |
| `js/student-draw.js` | 課堂抽選；維持既有行為，改善展示隱私及無障礙 |
| `tests/*.test.js`、`tests/*-browser.py` | 原有測試；擴增首訪、恢復與各功能交互的回歸測試 |

**已確認：**

- `app.js` 的 `init()` 在載入後呼叫 `saveWorkspace()`，**初次開啟也會自動寫入預設 601 班**。故 `localStorage` 有值／有一個班級**不能**等同於「已使用過」，這是歡迎頁觸發邏輯的首要陷阱。
- `storage.js` 使用 `localStorage.setItem()` 但儲存函式本身沒有 `try/catch` 或回傳結果，使用者可能無法知道存檔失敗。
- `index.html` 首屏直接呈現大量班級管理、學生欄位、教室配置、各模式操作；對新手缺乏清楚的「下一步」。
- 學生資料 textarea 示例包含「帳號、密碼、居住地點」，`app.js` 的學生卡可將密碼類欄位遮罩後再揭露；這不符合一般教室投影時的隱私預設。
- `index.html` 有外部 `https://polik18.github.io/assets/site-stats.js` 統計腳本；核心功能離線不表示整個網頁完全不對外連線。
- 同性別任務分組的組數／容量採貪婪分配，存在**可行分組卻回報失敗**的情境；現有 `tests/group-planner.test.js` 尚未完整涵蓋。
- ZIP 已有無實體座位學生、圓桌／U 型／島型自由教室、2–6 人任務分組。不要把它們當作完全未實作的功能而重新造輪子。
- 已執行五份 Node 測試：`effects`、`engine`、`group-planner`、`manual`、`room-layout`，**基線均通過**；它們不構成完整瀏覽器和使用者驗收。

**必須再次實測、不能直接視為已證實的事項：**旋轉桌組碰撞、圓桌增加座位後的位置重疊、密集 U 型布局在窄螢幕的點選可用性、調整桌組後排位資料是否意外消失、匯出 JSON 欄位是否含敏感內容。為這些問題先寫重現測試，再修正。

## 2. 產品定位：讓人看出融合教育，但不把學生貼標籤

### 2.1 雙層呈現策略

- **品牌層**（歡迎頁、首頁標題、說明與評審展示）：讓人理解它是一個「兼顧全班與個別學習需求的座位和合作學習工具」。
- **操作層**（教師配置）：用教學任務與環境需求描述，例如「先保留必要位置」「調整視線／動線」「檢查同儕互動」，將特教理念轉換成可操作步驟，而不是放「特殊生專區」。
- **學生／投影層**：一律不顯示任何支持需求、預排理由、障礙或特教標籤；全班看到同樣的中性座位卡與抽籤效果。

### 2.2 建議文案與微互動

- 主品牌：**SeatPlanner Inclusive**
- 中文產品名：**共融教室座位與合作學習**
- 歡迎頁主標：**每個位置，都有參與的可能。**
- 歡迎頁副標：**先照顧必要的學習條件，再輕鬆安排全班座位與合作活動。**
- 教師首頁的低調提示：**先保留需要的位置，剩下的交給抽籤或手動安排。**
- 功能名稱優先用「優先安排」「保留座位」「合作分組」「教室動線」，避免在座位圖／名牌上出現「特教學生」「障礙類別」「身分標註」。
- 可在「設計理念／為何這樣安排」的說明抽屜中溫和介紹「合理調整、通用設計、學生參與權」，**由教師主動打開**。

### 2.3 視覺方向（具體可實作）

- 友善、安定的教育工具而非競賽宣傳網站；以**奶油白、暖綠、柔和沙色**為主，橙色僅用於主要行動；具體色票由設計後依對比測試確定。
- 歡迎畫面採**原創 SVG／CSS 主視覺**：簡化的俯視教室座位、不同形式桌組、流暢動線與細緻的人物／葉片元素；不要使用「輪椅＝特教」等單一刻板象徵，不要用醫療十字、診斷符號。
- 首屏只有一個清楚的主操作：**開始使用**。次級操作：**匯入既有班級**、**跳過介紹**（或「直接進入」）、**語言切換**。
- 重要對比達 WCAG 2.2 AA 可達成的基本項目（一般字至少 4.5:1、大字至少 3:1、鍵盤可見焦點）；若未完整測試，不得宣稱整站已合規。
- Logo／命名一致：檢查既有 `Classroom Seat Master`／`CM` 與參賽名稱 `SeatPlanner Inclusive` 的落差，統一 title、頁首、備份檔命名與 README；不得修改 JSON 內容而導致舊檔無法辨識。

## 3. 介面資訊架構：由「所有工具同時顯示」改為「任務導向」

### 3.1 新首頁（首次教學後的常態畫面）

桌機首屏建議：上方品牌＋班級切換／教學說明／儲存狀態；中央保留**即時座位預覽**；旁側**任務進度卡**。常用路徑：

**建立／匯入班級 → 規劃教室 → 優先安排 → 完成排位 → 展示與備份**

- 任務卡顯示完成狀態，例如 `已匯入 29 位學生`、`已設定 29 個可用座位`、`已優先安排 2 位`、`可進行排位`；數字一律讀真實 state，不可寫死。
- **分頁／漸進展開**：基本設定預設展開，高階調整（性別座位限制、位置偏移、自由桌組幾何等）折疊到「進階設定」。
- 主要動作放在當前步驟內，按鈕以「儲存並前往下一步」「預覽座位」「開始排位」「展示結果」等實際動詞命名。不要讓首次使用者同時面對數十個不相關選項。
- 高階功能**仍保留**：手排、拖放、輪轉、班級複製、分組、抽學生、歷史紀錄、自由教室編輯等由進階入口進入；不可因簡化 UI 而刪除功能。
- 清楚區分「一般座位編排」「課堂活動（抽學生／任務分組）」及「資料管理（匯出／匯入／清除）」。
- 不新增有誤導性的「全部安全／完全匿名」標示。即時保存狀態區分：`儲存中`、`已儲存於此裝置`、`儲存失敗，請立即匯出`。

### 3.2 操作可理解性改造

- 每個步驟寫一句「目前要做什麼」、一句「為什麼」、一句「下一步」。空狀態提供實際按鈕，不只是空白畫面。
- 修正術語：`缺號`≠`不需實體座位`；`預排`不等於公布特教身分；`展示`不是重新抽籤；`匯入`不是登入雲端。
- 驗證錯誤就近顯示、描述解決辦法：例如 `可用座位 27 個，需要 29 個。請增加 2 席，或檢查不需實體座位名單。` 對應按鈕可直接定位問題欄位。
- 危險動作有二次確認、影響範圍與復原指示：刪班、重置、清空固定座位、修改已排位桌組。
- 既有 `role="tab"` 應補完整的 tabs 鍵盤行為與 `aria-controls`／`tabpanel`，或改成語意正確的按鈕；不得只靠視覺高亮表示狀態。
- 指南應可由 **「？操作教學」** 隨時再次開啟，也提供「返回步驟」而不是只能一路下一步。

## 4. 首次使用體驗（P0 需求）：歡迎畫面 + 下一步導覽

### 4.1 使用者旅程

1. **真正的第一次使用**：載入完成、判定無真實使用紀錄 → 出現全頁歡迎主視覺，背景應不暴露學生資料。
2. 點「**開始使用**」 → 進入 5–6 步互動導覽；可選「**匯入既有班級**」直接走匯入流程。
3. 導覽各步具 **上一步／下一步／跳過／進度 2/6**，以箭頭或視覺聚焦高亮對應真實功能，但不靠強制動畫。
4. 結束時顯示 `準備好了！`，主要 CTA `建立我的班級` 或 `開始編排`，導向班級基本設定；此時不應直接進入投影模式。
5. **下次正常開啟**：只要已完成／略過導覽、開始真實編輯、成功新增班級或成功匯入有效資料，便直接回到最近工作區，不再自動出現首次歡迎。
6. **手動重看**：由首頁 `？ 操作教學` → 再看歡迎／導覽；**不得因此重置班級或操作紀錄**。

### 4.2 導覽步驟（以現有實際功能為準）

| 步驟 | 畫面焦點 | 頁面上的簡短說明 | 操作 |
|---|---|---|---|
| 0：歡迎 | 專屬主視覺 | `每個位置，都有參與的可能` | 開始使用／匯入既有班級／跳過介紹 |
| 1：建立班級 | `#classSelector`、`#studentDataInput` 附近 | `先建立班級。可直接貼上試算表名單，也可以使用示範資料練習。` | 上一步／下一步 |
| 2：安排教室 | `#seatGrid`、行列設定與自由布局入口 | `依教室實況調整座位、走道與桌型。` | 上一步／下一步 |
| 3：優先安排 | `[data-admin-mode="prearrange"]` | `先保留必要位置；學生展示畫面不會顯示安排理由。` | 上一步／下一步 |
| 4：排位 | 抽籤／全手動入口 | `其餘座位可抽籤或手動安排，之後仍可微調。` | 上一步／下一步 |
| 5：展示與備份 | `#presentationButton`、`#exportButton` | `確認結果後展示，並匯出 JSON 備份你的班級設定。` | 完成教學／重看 |

**實作原則：** 指示框不能覆蓋被指示的按鈕；窄螢幕改為底部 step sheet；切換頁籤／步驟前，必要時把真實 DOM 控制項捲入視窗；目標 DOM 不存在時用非錨定說明卡安全降級；不要靠硬編碼畫面座標。

### 4.3 「只出現第一次」判斷的正式規格

**問題本質：** 啟動就會 `saveWorkspace()`、產生預設 601 班，所以不能把 `workspace != null` 當作已編輯；也不能單純把 `classes.length > 0` 當作已匯入。

新增**獨立於學生工作資料的**使用體驗 metadata，例：

```js
const ONBOARDING_KEY = 'seatplanner:ui-onboarding:v1';
// 僅示意，實作時須有安全 parse 與測試
{
  schemaVersion: 1,
  completed: false,
  dismissed: false,
  hasUserActivity: false,
  tourVersionSeen: 0
}
```

**不要把是否第一次使用直接寫成 `workspace.version` 或 `classes[0]` 的存在判斷**；新增 UI metadata 不必為此升級教室 JSON v4。新手導覽顯示規則請用可測試的純函式，例如：

```text
showFirstVisit =
  NOT completed
  AND NOT dismissed
  AND NOT hasUserActivity
  AND NOT isExistingMeaningfulWorkspace(workspace)
```

`isExistingMeaningfulWorkspace()` 必須基於原始載入資料與明確規則，不受初始化自動存檔影響：

- 真實活動訊號優先：**成功匯入有效 JSON、手動新增／複製班級、修改名單或班級設定、預排、手排、抽籤完成、建立分組、完成自由布局編輯** → `hasUserActivity = true`。
- **不要**把 `init()`、`render()`、`hydrate()`、`saveWorkspace()`、語言切換、導覽按「下一步」、程式自動建立示範資料視為真實活動。
- 既有舊用戶 metadata 缺失時，若發現**明顯非預設的有效工作區**（多班級、非預設班名／名單／座位／草稿／結果／活動），應直接當作既有使用者；不能僅因鍵值是 v4 就當作已使用。
- 若舊使用者的唯一資料**剛好與示範預設完全相同**，無法可靠辨識其使用史；採保守策略：可顯示一次**可關閉**的歡迎導覽，但**絕不改寫或清除其工作資料**。在 `README` 記錄此限制。
- 導覽做一半但**沒有真實編輯、沒有完成、沒有按「跳過」**便關閉頁面：下次仍可顯示歡迎（可選擇從第一步重新開始，避免狀態難以理解）。
- 使用者按「跳過介紹」或「直接進入」：寫入 `dismissed=true`；下次不再彈出。
- 成功匯入既有班級的 JSON：先 `readImport()` 驗證、再成功 `importClasses()` 後才標記使用活動。**失敗匯入、取消檔案選擇不算**。
- `index.html` 目前使用 JSON 及多班級工作區，**沒有「自動偵測裝置上的班級資料夾」能力**。一般瀏覽器不能無授權掃描本機資料夾。因此使用者口中的「已有匯入班級的資料夾」在本次最小實作定義為「已有持久化班級工作區或成功匯入 JSON」；若後續要支援資料夾選取，必須經使用者明確授權，另開需求，不能假裝已能偵測。
- 完成／略過旗標只影響導覽，不影響業務資料；清除資料時是否重顯第一次教學應明確設計：`重設全部並重新開始` 可以一併清除；一般 `刪班級` 不應重設導覽。
- `localStorage` 拒絕寫入、無痕模式、配額滿或資料損壞時，不得靜默聲稱下次不會顯示；要提供非阻斷提示，且不可覆寫損壞的原始資料。

### 4.4 建議以表格驅動測試的狀態矩陣

| 進入狀態 | 本次自動彈歡迎 | 下次開啟 |
|---|---|---|
| 全新瀏覽器、無資料 | 是 | 尚未完成／略過／編輯則仍可顯示 |
| 只有 `init()` 自動產生預設 601 班 | 是 | 仍屬未使用，應顯示 |
| 導覽第 3 步直接關閉頁面，無編輯 | 是（再次造訪） | 直到明確結束或開始使用 |
| 按「跳過介紹」 | 否（立刻退出） | 否 |
| 完成全部導覽 | 否 | 否 |
| 在導覽後實際更改班級或座位 | 否（應結束／收合導覽） | 否 |
| 成功匯入有效多班級 JSON | 否 | 否，恢復匯入工作區 |
| 選了取消或錯誤的 JSON | 維持導覽 | 不可標記為已匯入 |
| 舊版本工作區含真實資料，但沒有 metadata | 否 | 否 |
| 點「重新觀看教學」 | 本次自願顯示 | 之後仍不自動顯示 |
| 一般刪除其中一個班級 | 否 | 否 |
| 明確點「清除全部資料並重設新手教學」 | 是 | 是 |

### 4.5 導覽互動及無障礙規格

- 歡迎層是可存取的 `<dialog>` 或正確實作 `role="dialog" aria-modal="true"`；開啟時移入焦點、關閉後還原焦點；Tab 不穿透至背景；Esc 關閉行為與「略過」一致。
- 文字與示範圖可不用任何外部資產；主視覺要有可理解的 `aria-label`／替代敘述，純裝飾元素 `aria-hidden="true"`。
- 導覽包含可見進度、簡單的步驟標題、上一步／下一步、略過；每次步驟更換要更新螢幕閱讀器公告；不應自動播放聲音。
- `prefers-reduced-motion: reduce` 下停用非必要 transition；手機避免被 fixed footer 與輸入法遮住，仍可點擊跳過。
- 最小使用尺寸至少覆蓋 360px 寬手機、768px 平板、1280px 桌機；高達 200% 縮放時仍能完成導覽，關閉視窗、輸入、匯入。

### 4.6 建議新增檔案與 API（可調整，但需合理拆分）

```text
js/onboarding.js            首訪顯示決策、導覽 state machine、DOM 事件與 focus 還原
js/onboarding-storage.js    metadata 安全讀寫及舊使用者判定（或納入 storage.js）
tests/onboarding.test.js    無 DOM 的狀態決策／遷移單元測試
tests/onboarding-browser.py 具有真實 DOM／localStorage／匯入的 E2E 測試
```

`index.html` 新增獨立歡迎／導覽容器及入口按鈕，腳本載入順序須先 `constants/i18n/storage`，再 `onboarding`，最後 `app.js`；避免形成循環依賴。`app.js` 只需在 `init()` 完成 hydration、bind events、render 後呼叫 `onboarding.startIfNeeded({ initialWorkspaceSnapshot, ... })`，並從使用者真實互動事件通知 `onboarding.markMeaningfulActivity(...)`。注意 `initialWorkspaceSnapshot` 必須**在自動持久化預設資料前取得**。

## 5. P0：修正既有邏輯與隱私問題（不能被 UI 改版掩蓋）

### 5.1 任務分組正確性（`js/group-planner.js`）

- 先寫回歸測試：8 人、6 男 2 女，目標每組 4 人，選同性別策略；正確結果應允許 **6 人一組＋2 人一組**，而非硬性每組 4 人。其他如 7 男 1 女在完全同性別且 2–6 人硬限制下可能無解，應明確提示；**不得偷渡單人小組**。
- 替換貪婪式分配：先對各性別／預排／鎖定成員求**可行組數和各組容量**，再分配隨機學生；先驗證可行性再執行，最後再次執行 `validate()`，不可只返回表面成功結果。
- 待測：2、3、4、5、6、7、8、11、13、29、30 人；混合、均衡、同性別三種策略；預排、鎖定、未指定性別、無實體座位但仍參與活動、重抽與多次操作。
- 分組不應自動依**障礙類別**決定配對；「同儕合作」支援輪替與教師覆核，不推論學生被需要陪伴的身分。

### 5.2 隱私與投影資料隔離（`index.html`、`js/app.js`、`js/ui.js`、`js/storage.js`）

- 移除示例的「密碼、帳號、居住地點」，改成 `座號、姓名、備註（僅限可公開的教學資訊）` 等中性範例。
- **正式展示模式只允許白名單安全欄位**：預設座號／姓名；其他欄位必須由教師明確開啟且先經預覽確認。不得在學生卡使用可點擊揭露密碼的按鈕；對舊 JSON 內的密碼、電話、住址等欄位，投影一律不顯示。
- 管理畫面也應警示勿輸入 IEP、診斷、聯絡方式、帳密、住址等敏感內容；不將正式教學紀錄直接存到此工具。
- 不要以「只是遮罩」當作安全機制；localStorage 和 JSON 都是明文，需於 README 與匯出確認文案如實提醒。
- 移除正式參賽／離線入口的外部 `site-stats.js`；檢查所有 `http(s)`、字型、圖示、CDN、analytics、service worker，以離線 network log 驗證無意外請求。
- 對敏感資訊是否已被上傳**不要作未驗證的歷史性斷言**；僅能證明新版在測試條件下的行為。

### 5.3 資料完整性／錯誤回饋（`js/storage.js`、`js/app.js`）

- 在 `storage.save()` 捕捉配額、權限等寫入例外並回傳 `{ok, error}`，UI 據此顯示明確失敗；不可仍顯示「已儲存」。
- 匯入採兩階段：`讀取並驗證 → 預覽資料摘要 → 使用者確認 → 合併或取代`，錯誤檔不改變現有資料；刪除及取代須確認。
- 原始資料版本維持可讀：匯入 v1/v2/v3/v4 → 正規化；匯出仍可與目前正式 v4 相容；任何版本變更需提供升級測試與備份。
- 區分**資料是否確實存檔**和**是否被視為已使用過**；這兩者使用不同機制，不能因為 `saveWorkspace()` 被呼叫而更新首訪 metadata。
- 若使用者修改教室造成既有座位不再合法：先產生變更影響清單；盡可能保留仍合法的 assignment、pin、manualDraft、活動紀錄；僅將衝突者移回待排或要求確認，並提供復原。
- 增加匯出時的敏感資料警語，但不要在備份時默默刪除舊檔字段而破壞可恢復性；提供「去敏展示／分享版」與「完整本機備份」兩個清楚不同的用途（若當期無法完成，至少不得預設分享完整備份）。

### 5.4 教室布局與通道（`js/room-layout.js`、`js/ui.js`）

- 為桌組旋轉後的幾何碰撞與通道重疊加入測試；判斷應考慮桌組實際旋轉、座位卡大小與有效桌邊界，而非只看未旋轉 bounding box。
- 圓桌更改座位數時，所有席次位置需重新分配且保留可對應座位 ID／已排學生；不要讓新座位與原位置重疊。
- U 型等高席數配置須依容器尺寸調整、縮放、平移或提出「目前過密」警告；不能用自動覆蓋卡片方式假裝已完成。
- 動線圖只能說是**規劃輔助**，不宣稱自動符合法定無障礙通道寬度；仍需教師現場確認。
- 以上項目先重現再修復，新增失敗案例到 `tests/room-layout.test.js` 與瀏覽器 E2E。

## 6. P1：讓特教價值落在教學流程，而不是標籤

### 6.1 教師端「合理調整」引導卡

- 新增選填的「安排前想一想」：視線／聆聽、環境干擾、可達動線、互動與合作機會四種**環境條件**，不是障礙診斷清單。
- 支援「先保留位置，再分配其餘」的教師操作提示、避免長期固定同儕責任的提醒。必要時可記錄**非敏感的環境調整代碼**，預設不保存具體理由；不創建新的學生診斷欄位。
- 只顯示在教師編輯場景，**絕對不能**透過展示頁、JSON 分享版或學生資料卡曝光個別需求。
- 不宣稱系統可推斷 IEP 或自動決定誰應坐哪裡；只提供教師決策輔助。

### 6.2 合作學習與觀察回饋

- 加入「同儕組合輪替提醒」，依既有活動分組歷史告訴教師 `這兩位最近常同組，是否調整？`；避免以性別或特殊身分自動決定學生的能力、角色。
- 提供**空白、可列印／去識別化**教學觀察表：學習參與、同儕合作、課堂適應三向度，提醒教師記錄活動、情境與觀察日期。
- 若未具備真正教學資料，畫面只能展示 `觀察表範本`、`待紀錄`；不得顯示虛構百分比或「改善 XX%」。
- 教師有權不使用上述進階功能；核心 5 步排位流程仍簡單完整。

### 6.3 展示模式的普及設計

- 大字級、高對比、少動畫／無動畫、靜音；跟隨 `prefers-reduced-motion`；勿讓聲音或快速動畫成為唯一提示。
- 投影畫面優先使用中性視覺、清楚字號、座號和姓名；禁止暗示某位學生「受到特殊照顧」。
- 支援鍵盤完成主要操作；不得只有拖曳可調整座位。

## 8. 自動化測試清單（必寫成可重跑測試）

### 8.1 首訪／導覽

- `clean storage` 首次開啟顯示歡迎；`init()` 自動建立示範班級**不**阻止歡迎。
- 歡迎主視覺、開始、上一／下一步、完成、略過、重新開啟可運作。
- 導覽進度與聚焦的控制項一致；換頁後目標可見、焦點不遺失。
- 導覽做到一半重開：未編輯且未完成可再次看到；有真實編輯不再自動看到。
- 成功匯入有效 JSON 不再彈出；匯入失敗／取消不應誤判為使用者已經匯入。
- v4 舊資料、多班級、舊 v1–v3 檔移轉後保留原內容；舊資料使用者不被強制導覽。
- 老師手動重看導覽，不更動 `state`、`assignment`、`manualDraft`、`activities`。
- 重設班級和清空所有資料的不同導覽行為符合規格。
- 隱私模式或禁止 localStorage 時 UI 提示合理，不會當作永久保存成功。

### 8.2 排位／分組／布局

- 29–34 人常見班級、缺號、性別限制、固定座位、無實體座位學生、名單貼上與重複座號。
- 8 人 `6M/2F` 同性別策略 2–6 人合法分組可成功；`7M/1F` 不可行時有合理解釋。
- 每組成員均不重複、不漏人、不超過 6 人，且除規格允許的特殊情況外不少於 2 人。
- 更改座位形狀、旋轉桌組、圓桌加座位、高密度 U 型、通道與桌碰撞、旋轉整間教室，座位 ID 與 assignment 不意外錯置。
- 調整／刪除座位必須保留未受影響的排位或在無法保留時提示並可復原。
- v4 JSON 匯入匯出 round-trip，完整結果、活動與草稿一致。
- 模擬 `localStorage.setItem` throw；使用者可看到失敗並備份，而不是誤判已存檔。

### 8.3 UX／隱私／可近用性

- 360px、768px、1280px 及 200% 瀏覽器縮放：導覽完整可操作且不溢出重要動作。
- 完全鍵盤：Tab／Shift+Tab、Esc、Enter、Space 可以進入及關閉歡迎、完成導覽、操作主要任務。
- `prefers-reduced-motion` 正常；展示靜音無故障。
- 展示模式不含預排原因／障礙標籤／密碼、住址、聯絡方式；舊 JSON 導入含敏感自訂欄仍不可直接展示。
- `file://` 離線開啟無外部服務依賴；相同核心功能在 GitHub Pages 線上可運作。
- 若未安裝 Playwright/Chromium，記錄環境阻礙；**不可以 Node 單測代替宣稱 E2E 通過**。

- 要求參與者以自己的話描述工具用途，至少能理解「兼顧個別需要與全班參與」，而不是只有「隨機抽籤」；不要求主動使用「特教」字眼。

## 12. 使用者新增需求修訂：班級紀錄與同儕分開安排（研究／規劃，尚未實作）

本節為原 Phase 0–5 之後的新需求，優先修訂原計畫對「保存班級」「優先安排」與資料格式的定義。2.0 已交付程式及 ZIP 不因本次文件修訂而改變。

詳細研究、資料設計、R0–R5 實作順序與驗收案例：[班級紀錄與同儕分開安排修訂計畫](E:/Git/SeatPlanner-main/docs/inclusive-2.1-class-records-and-separation-plan.md)。

1. **真正可保存的班級紀錄**：新增「我的班級」「儲存班級」「開啟紀錄」、學期整理、具名排位版本、單班完整檔案、封存與復原。明確區分自動暫存、具名儲存與外部備份；每班保存名單、教室、規則、草稿、結果與活動。抽學生輪次一併改成隨班保存。班級教學日誌如也需要，另定欄位與隱私範圍，不宣稱空白觀察表已能保存紀錄。
2. **可事先設定誰與誰分開**：除固定預排，新增雙學生配對的硬性限制。「不相鄰」網格預設包含左右、前後與斜角；「不同桌組」另列。自由布局必須有可預覽／確認的鄰接定義，不用螢幕像素或座位 ID 猜測。
3. **抽位必須遵守**：有規則時使用受限制的隨機求解，成功候選再經獨立驗證才揭曉。固定位置衝突、已證明無解、尚未找到結果／逾時及取消分開回報。不得默默放寬限制或以反覆重抽當作正確性保證。
4. **所有操作共同檢查**：手排、交換、旋轉／布局變更、匯入、歷史還原及展示均檢查新硬限制。原本手排可略過性別與固定條件的政策，不適用於新增的配對硬限制。無效草稿可保存為未完成，不能公開為合格結果。
5. **身分與遷移**：班級與學生增加穩定身分；改座號或同座號換新學生不可錯套限制。建議正式設計 v5 與新儲存鍵，保留 v1–v4 讀取、原值備份及測試，不將會被舊版忽略的新規則藏在 v4 備份中。此為本需求所需的規劃變更，目前未執行資料遷移。
6. **教師專用、公開隔離**：完整教師備份保留規則，展示／公開列印／去敏分享不包含配對規則、學生內部 ID 或安排理由。不將座位配對自動擴大成課堂活動的禁止同組規則。
7. **新增驗收門檻**：關閉再開仍找得到班級與版本、單班檔跨瀏覽器還原、多班不串資料、重抽零違規、小案例與窮舉比對、無解／逾時區分、固定位置衝突、手排與交換無繞過、自由布局與遷移／隱私測試。全部屬待實作驗收，不能沿用 2.0 的通過紀錄宣稱新功能已完成。

# SeatPlanner 美編與排版設計提案

狀態：完成現況檢查與獨立版面原型，尚未套用正式介面。原型：[`visual-design-preview.html`](visual-design-preview.html)，可切換管理、編輯、展示三種版面。原型使用示意座號，不連接或改動正式班級資料。

## 設計判斷

目前已有溫暖色調與較精緻的歡迎視窗，主要問題在於各畫面的視覺層級還沒有統一。主畫面說明過多且卡片層層包覆，教室圖被推到下方；手機頁首堆疊多排同等重要的按鈕，進入頁面後很久才看到座位。編輯器的外框比例、尺寸及精確設定有重複標題，四個比例按鈕直排，占用過多高度。

建議方向是「溫暖、清楚、以座位圖為中心」。美編要服務老師的工作，不再增加大幅裝飾或長篇宣傳區塊。最醒目的用途仍是私下預排與同儕分開；公開展示則保持所有學生一致的視覺待遇。

## 1. 主畫面的新層級

1. **頁首**：品牌、暫存狀態、班級紀錄、開始展示。操作教學、語言、抽學生、任務分組等整理為次要工具，手機收納至有文字標示的選單。
2. **班級標題**：班名、目前狀態、一行說明，不再重複品牌名稱或巨大裝飾字。
3. **兩項核心入口**：預排個別座位、同儕分開，各有一致的線條圖示、標題及一句用途說明。長篇理由與使用提醒按需展開。
4. **座位圖工作區**：學生數、容量、編輯教室與排位工具整合在圖的標題列；管理者可在第一屏看到座位圖，而不必先捲過整頁說明。
5. **次要設定**：班級、名單、版型、進階規則、資料工具分組；不必每個子區都再包一張不同底色卡片。

原型以三階段導覽示範「建立班級 → 安排座位 → 展示結果」，用於降低視覺負擔。正式實作時可保留目前五步功能，將教室與預排入口整合進安排階段；這是導覽整理提案，不能直接刪除既有功能。

## 2. 色彩規範

| 用途 | 建議色彩 | 使用方式 |
| --- | --- | --- |
| 頁面底色 | `#F5F2EA` | 溫暖淺底，保持安靜 |
| 內容表面 | `#FFFEF9` | 表單與工作區，少用多層底色 |
| 主要文字 | `#21392B` | 標題與內文 |
| 次要文字 | `#586657` | 提示與說明，仍須清楚可讀 |
| 主要操作 | `#27533D` | 當前頁的主要行動、選取狀態 |
| 淺綠背景 | `#EDF3E9` | 核心功能入口，避免整頁到處都是綠卡 |
| 邊線 | `#DCE2D7` | 區塊界線與表單 |
| 暖金 | `#A57C42` | 少量編號與裝飾，不作小字正文的預設色 |
| 編輯選取 | `#2563A6` | 焦點與幾何控制點，和一般功能綠區別 |

顏色必須伴隨文字、圖形或狀態名稱。男女座位、錯誤及警告保留原有語意，另驗證對比，不能為了色調一致而讓狀態難以辨識。

## 3. 字級與留白

- 一般介面內文以 14–15px 為主，表單標籤至少 13px；12px 用於次要提示。小尺寸標籤不可承載必要操作資訊。
- 頁面主標題約 24px、區塊標題約 18–20px，避免多個同尺寸大標題互相競爭。
- 中文內文行高約 1.7–1.85；長段落限寬，避免滿版長行。標題使用自然換行，避免手機最後一字孤立成行。
- 統一 4／8／12／16／24／32px 間距，區塊間距大於區塊內間距。
- 圓角採 8px（欄位）、12px（功能入口）、16px（主要面板）三層；浮出式視窗可使用 20–24px。
- 陰影主要用於浮出視窗與選取層；一般表單與每張座位不需要厚重投影。

編輯畫布是例外：圖形與內部文字維持同一個邏輯倍率，不能套用一般介面最小字級而再次把字放大到超出圖形。

## 4. 按鈕與圖示

同一區域原則上保留一個主要行動；其他使用描邊或文字按鈕。刪除與重設以明確文字標示，收在資料操作區，不與開始展示並排搶眼。

圖示統一使用簡單線條 SVG，尺寸約 18–20px、線寬一致。核心用途保留文字名稱，不以混合風格的 emoji、實心符號及裝飾字代替。選取、停用、滑過與鍵盤焦點狀態需成套設計。

## 5. 編輯器屬性面板

- 標題只顯示一次目前選中的物件，例如「教室形狀」。
- 寬、高同列；常用比例以一列小按鈕排列，自訂長寬比與鎖定比例放在一起。
- 將改形狀、位置及觀看倍率清楚分組；「等比適配內容」歸入配置調整，不和看全圖放在同一組。
- 屬性使用短標籤與就近說明，取消重複的外框標題、重複尺寸表單及每個比例都滿版直排的做法。
- 選取輪廓與控制點維持藍色，標記和文字仍同步縮放；保留大型畫布、固定相機、平移與放大選取功能。

原型的編輯版只展示排版方向，沒有幾何編輯引擎，不能視為已實作替代品。

## 6. 展示畫面

以班名、座位與必要教室標記為主，拿掉管理工具與設定說明。座號、姓名依使用者顯示設定排版，字級與卡片大小協調。空位使用低對比虛線，不能和學生卡片同樣醒目。

預排學生與其他學生使用完全相同的顏色、邊框、動態及資訊層級；不新增會暴露分開配對的圖例或標記。原型切到展示後會隱藏管理入口，作為此原則的示意。

## 7. 歡迎與教學

保留目前浮出視窗、背景柔化與短動畫。品牌色、圓角、按鈕、字級與新主畫面一致。原有介紹圖片完整保留，不再把圖中文字當作主要操作說明；關鍵用途用 HTML 文字呈現，維持清晰度與可及性。

動畫以 160–300ms 的淡入、位移或進度變化為主，只有進場可稍長；避免持續閃動與無限裝飾動畫，沿用減少動態效果支援。

## 8. 手機排版

首屏優先出現班名、兩個核心入口及座位圖的開頭；完整設定放在後方或可展開的面板，不能先堆一整頁說明。

頁首以一個主要行動搭配次要選單呈現，不把所有工具都塞成多排大按鈕。欄位改單欄或簡單雙欄；次要文字可精簡，但必要資訊保持至少 12px。原型中的座位與教室標記是縮圖示意，正式套用時仍須依教室畫布的共同倍率呈現，不能照抄固定像素尺寸。

手機編輯器仍沿用大畫布和可收合底部屬性面板，不能為了把所有控制項塞進首屏而重新縮小教室圖。

## 9. CSS 整理方式

現有 `assets/styles.css` 有多段同名選擇器及較早版本的覆寫，例如 `:root`、`.welcome-dialog`、`.tour-panel`。正式改版時應先整理設計變數與元件區塊，逐段替換，避免繼續在檔尾疊加互相衝突的樣式。

整理分為：設計變數、基礎字體、通用元件、管理版面、教室畫布、展示、歡迎教學、響應式與可及性。保留既有 DOM ID 與功能事件；涉及 DOM 移動時，另檢查委派事件、焦點與隱藏狀態。

## 10. 實作順序與驗收

1. 先確認這份原型的視覺方向，固定色彩、字級、間距與按鈕樣式。
2. 優先整理主畫面與手機首屏，讓座位圖更早出現，同時保留兩項核心功能的醒目入口。
3. 整理編輯器屬性面板，再統一展示、歡迎、教學與班級紀錄視窗。
4. 執行現有功能回歸，並以相同班級、相同螢幕截圖比較，不能只確認「程式沒報錯」。

驗收尺寸至少包括 1366×768、1280×720、1920×1080、768×1024、390×844，以及瀏覽器放大 200%。檢查必要字級、對比、鍵盤焦點、觸控目標、文字溢出、座位圖可見面積，以及編輯前後幾何比例。須額外確認展示沒有透露預排或分開設定。

本次只提供設計文件與獨立原型，尚未變更正式排位介面、資料格式或儲存內容。

## 問題摘要

目前教室畫布能移動或旋轉整桌，但座位不是桌組內的獨立版面物件。使用者因此無法修正桌位密度、桌型幾何或單一座位位置；「增加座位」只把 seat ID 加入清單，畫面接著用固定公式重新計算全部座位位置。

U 型配置尤其明顯：目前 U 型演算法只在上緣和兩側平均分配少量點，再把剩餘座位交替塞到左右側；它沒有 U 型開口端、長邊容量或每邊座位數等概念。學生人數多時，座位會堆在一起、落到桌組範圍外，且畫布設有 `overflow: hidden`，超出的內容直接被裁切。圓桌和矩形桌雖有各自的簡化點位公式，但仍沒有可保存的單席座標；固定 72px 的座位卡在密集桌組上也容易碰撞。

目前相關實作位置：

- `js/room-layout.js`：`seatPoints()` 由桌型及座位總數即時計算位置，資料模型沒有 seat position。
- `js/ui.js`：每次渲染呼叫 `seatPoints()`，以百分比把座位畫在桌組元素內；桌組旋轉會連同整個內層內容旋轉。
- `js/app.js`：拖曳只移動桌組／通道；增加或移除座位只增減 ID，沒有位置編輯或可配置的每桌容量欄位。
- `assets/styles.css`：桌組與座位均由巢狀 DOM 絕對定位；座位卡固定尺寸，畫布會裁切超出範圍的內容。

## 設計方向

把教室編輯器改成「桌組、桌面、座位、通道」四種可辨識且可分別選取的空間物件。桌型模板只負責建立初始幾何；建立後，每張桌的座位數與每個座位的位置都要成為可編輯、可儲存的明確資料。

採用兩層座標：每張桌以畫布百分比保存位置、寬高與角度；座位以該桌局部座標保存位置。移動或旋轉桌組時，座位隨桌移動；編輯單席時，只改該席局部位置。桌型重新產生座位時提供「保留現有座位並補足／重排全部座位」明確選項，避免調整桌型後手動成果被意外覆寫。

畫布可用 SVG 或等效的單一向量場景承載桌面、座位、選取框與調整控制點，座位資訊卡仍可保留 HTML 內容層。採用向量場景的目的，是讓桌面輪廓、座位錨點、拖曳命中區和旋轉共用同一幾何座標，不再由多層固定尺寸 DOM 各自猜位置。實作前用小原型比較 SVG 與現有 DOM overlay；若可存取性或內容卡片無法可靠呈現，保留 HTML 座位卡但以 SVG path/anchor 提供幾何和拖曳控制。

## 編輯操作規格

### 1. 清楚的選取與編輯模式

- 保留「編輯桌組與動線」開關；編輯時顯示物件邊界、選取框、尺寸控制點及座位編號，非編輯時隱藏控制點。
- 點桌面選取桌組；點座位選取單席。鍵盤 Tab 可在桌組、座位和通道之間移動焦點，Enter 選取，Escape 回到桌組／畫布。
- 選到桌組時，右側或工具列屬性區顯示桌型、桌名、寬、高、角度、座位數、座位布局與「自動排座位」操作。
- 選到座位時顯示所屬桌、座號／座位標籤、局部 X/Y 座標、角度（需要時）及「回復到自動位置」。提供可拖曳操作，也提供數值／方向按鈕以便觸控和精細調整。
- 畫布支援縮放、平移及「重設視圖」；座位卡視覺大小與編輯控制點保持可操作，不因縮小桌面而變成極小點。

### 2. 桌型與座位數

- 桌型至少包含矩形、圓形、U 型。每張桌有獨立座位數，提供數字輸入及 +/- 控制；座位數最小為 1，最大值由桌面空間及可讀性限制，不以全班總人數硬性封頂。
- 桌型設定提供常用布局參數：
  - 矩形桌：各邊座位數（上／右／下／左）或總數後自動均分。
  - 圓桌：總數、起始角度、座位半徑。
  - U 型桌：上邊、左臂、右臂座位數，開口方向，以及桌臂厚度／內部淨空。
- 座位布局提供「平均排列」、「沿桌邊排列」、「手動排列」三種狀態。U 型「沿桌邊」必須只在兩臂與封閉端放位，開口側不放位；除非老師明確切換為手動，不能把超額座位偷偷塞到桌臂內側或外側。
- 自動排列應以實際桌面尺寸、座位卡寬高和最小間距計算，展示預覽及碰撞／超出範圍提示。不能靠 CSS 裁切掩蓋無法容納的座位。

### 3. 單席調整

- 每個 seat ID 有穩定身分及局部座標（例如 `x`, `y` 取 0–100%）；座位移動、桌組移動、桌組旋轉、桌型切換後仍以 ID 保留學生 assignment、pin 及任務桌位關聯。
- 拖曳座位時以桌組為邊界吸附，可選擇格線吸附；允許為無障礙需求關閉吸附。
- 允許「沿桌邊方向移動」及自由移動；座位彼此太近或超出桌組邊界時顯示即時提示，允許老師暫時保留重疊但需有可見標示，不可靜默消失。
- 增刪座位時只影響被增刪的 seat ID。刪除已有人、已固定或被任務使用的座位時，先將相關 assignment 釋放回待排，並顯示受影響數量；提供復原。

### 4. 直接操作與精細屬性並存

- 桌組和座位均可拖曳；鍵盤方向鍵以小步移動，Shift+方向鍵以較大步移動，Alt+方向鍵調整角度（按鍵組合可依平台無障礙慣例微調）。
- 所有重要幾何操作提供可鍵盤操作的按鈕或數值輸入，不把拖放作為唯一途徑。
- Undo／Redo 覆蓋桌組、座位、桌型、容量、通道幾何與座位自動重排；跨越刪除前的狀態可完整恢復 assignments。
- 新增桌組的複製操作應明確選擇「只複製桌型／位置」或「連同座位數與布局複製」；複製時生成新的 seat IDs，不能重複引用原 ID。

## 資料模型與相容性

自由教室資料需升版（建議應用資料 v2→v3；實際版本號以實作盤點為準），舊資料仍可匯入。建議桌組模型：

```json
{
  "id": "table-1",
  "type": "u",
  "x": 50,
  "y": 50,
  "width": 48,
  "height": 42,
  "rotation": 0,
  "geometry": {
    "opening": "bottom",
    "armThickness": 12,
    "seatLayout": "perimeter",
    "edgeCounts": { "top": 6, "left": 4, "right": 4 }
  },
  "seats": [
    { "id": "free-1", "x": 20, "y": 18, "angle": 0, "label": "1" }
  ]
}
```

為降低一次遷移範圍，可以繼續在 `state.seats` 儲存 assignment 與限制屬性，把可編輯座位幾何放在 `roomLayout.tables[].seatPositions`，再由 seat ID 關聯。長期可將 geometry 與 assignment 聚合成 table-owned seat object，但這次不必同時重寫全站座位 assignment API。

遷移 v2 自由版型時：

1. 保留桌組 ID、桌型、中心點、寬高、旋轉、paths 和全部 seat IDs。
2. 以舊 `seatPoints(table, count)` 產生一次初始局部座標，寫入新 `seatPositions`；舊 U 型會有超出／重複風險，遷移時改用新的自動布局演算法並記錄遷移版本。
3. 舊桌位已有 assignment、pin 或活動座位關聯時，僅改幾何位置，不改 ID；無法映射的重複／無效 ID 匯入時做去重並回報。
4. 舊網格→自由版型仍保留目前映射規則；自由版型→網格如有不相容幾何，提示教師先匯出備份，並提供座位按穩定 ID/順序映射的預覽。
5. 匯入舊 v1／v2 JSON 及 localStorage 必須可讀，匯出後重載幾何須一致。

- 新增每桌座位數控制及矩形邊位／圓桌半徑／U 型三邊和開口設定。

### Phase C：單席位置編輯

- 讓座位可獨立選取、拖移、鍵盤移動及以 X/Y 調整位置。

### Phase D：精修編輯器與資料遷移

## 驗收條件

- U 型桌預設只在封閉端和兩側放椅，開口清楚可見；12、24、34、40 席情境不因演算法把座位疊在一起或裁出畫布。空間不足會明確提示，不隱藏座位。
- 圓桌、矩形小組桌可各自設定座位總數；矩形桌可調每邊數量；U 型可調開口方向與三邊人數。
- 任一座位可被單獨選取並以拖曳、鍵盤和數值欄位調整位置；重載後座位位置相同。
- 桌組移動／旋轉不改 seat ID、學生 assignment、固定座位和任務座位關聯；單席移動只改該席幾何。
- 新增／刪除座位有明確的 assignment 釋放行為；Undo 可還原桌位與座位關聯，Redo 可重做。
- 桌組及單席均有可操作的觸控命中區；縮放後仍可選取，手機不會因畫布寬度而無法操作關鍵控制。
- v1／v2 資料可載入和匯出；自由版型 v2→v3 遷移維持 ID 並產生有效初始座位座標。
- Playwright 測試涵蓋 U 型 34 席不重疊、圓桌增加容量、移動單席、鍵盤操作、Undo／Redo、重載及 v2 JSON 匯入。

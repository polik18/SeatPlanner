# SeatPlanner 增功能計畫（2026-10）

## 實作狀態

本計畫的核心需求與驗收流程已落地：無實體座位名單、自由教室桌組／通道、2–6 人任務分組及任務座位安排，並有 v1→v3 遷移、Node 單元測試和 Playwright 瀏覽器流程。細節以 README 的功能與測試命令為準。自由教室座位位置編輯正在依 [改善計畫](room-layout-improvement-plan.md) 分階段實作。

## 目標

在保留離線使用、手動排位、預排座號、本機保存與 JSON 匯入匯出的前提下，新增三種教室／活動情境：

1. 名單可包含不需要實體座位的學生，仍能完成座位表。
2. 教室可用桌組與座位位置表達小組桌、圓桌、U 型配置及輪椅通道。
3. 臨時任務可把全班抽成每組 2–6 人，預先安排、抽籤、手動調整，並按男女需求分組。

## 現況盤點

- 專案是無伺服器靜態網頁，直接開啟 `index.html`；設定與草稿存在 `localStorage`，設定可匯出為 JSON。
- `js/seat-engine.js` 的名冊由最大座號、缺號及女生起始座號建立；每筆學生都有座號與性別。座位是 `row-col` 矩形網格，座位型別為不限、男生、女生、走道。
- `engine.validate()` 要求可用座位數不少於全部有效學生數；`js/manual-seating.js` 的完成條件也是全員排入實體座位。這是「無實體座位」需求的主要資料與流程阻礙。
- `js/ui.js` 依行列產生座位 DOM，`assets/styles.css` 用 CSS Grid 顯示；旋轉依行列座標重新映射。非矩形空間與桌組不能只靠調整 CSS 達成。
- `js/student-draw.js` 已有全班名單、抽取多人、不重複、逐輪紀錄與本機保存，但沒有分組概念，也不能將名單分派到桌組。
- `js/storage.js` 固定 `VERSION: 1`，JSON 包含 config、座位、結果、管理模式與手動草稿。擴充空間模型及活動結果需要明確遷移策略。
- 現有測試涵蓋引擎、動畫時序、手動排位及瀏覽器操作。專案無獨立 checkpoint；本次盤點的 Git 工作目錄乾淨，`main` 與 `origin/main` 同在 `16a5fd1`。

## 產品規格建議

### A. 名單學生與實體座位分離

- 每位學生仍是班級名單成員；另存「需要實體座位」狀態，預設為需要座位。此狀態不能以缺號表示，因為學生仍可能參加抽人或活動分組。
- 手動排位待排區增加「不需實體座位」名單區。老師可將學生標記為無實體座位，亦可隨時改回需座位；座位表只呈現需要座位的學生。
- 抽座位、性別座位容量驗證、固定座位和完成條件只計算需要實體座位者。無座位學生不得被固定到座位；未入座名單仍可查看及修正。
- 「不需實體座位」不等於缺席或不參加任務。任務編組時另提供參與名單選擇；預設包括全部有效學生，避免意外把遠距或臨時不在場者排除。
- 舊檔所有學生預設為需要實體座位，因此舊版讀取後顯示和完成條件不變。

### B. 可配置桌組與通道的教室

- 保留「矩形網格」作快速起始版型和舊檔相容模式；新增「自由教室配置」編輯器。
- 自由配置由可移動的桌組構成。桌組至少支援單桌、矩形小組桌、圓桌、U 型桌；每個桌組可設座位數及座位順序，學生仍落在明確的實體座位 ID 上。
- 編輯器可拖移、旋轉、複製、刪除桌組；支援縮放、吸附格線、復原／重做。學生位置與桌組位置分離保存，調整桌型不得改變學生身分或任務分組。
- 可在畫布標示輪椅可通行區／主要動線，該區不生成座位；通道寬度可設定並可視化。這是排位輔助標示，不宣稱自動符合建築或法規標準。
- 管理模式中顯示桌組、走道與座位編號；展示模式隱藏限制標記但保留空間圖形。手機上可平移縮放，避免把拖放作為唯一操作方式。
- 首版不重做現有四周黑板／門／教師標記功能，先使其能錨定在教室邊界；重新定義輪轉和任意角度旋轉留在自由配置階段處理。

### C. 臨時任務分組與座位安排

- 新增獨立的「任務分組」工作區，不覆蓋日常座位表。建立任務時選名單、目標每組人數（2–6）、性別策略及是否套用到實體座位。
- 抽組採公平亂數打散，再平衡各組人數。只要有效學生數大於 1，各組盡量維持 2–6 人；不足 2 人時清楚提示例外，不靜默產生不符合設定的組別。
- 性別策略至少含：不限制／隨機混合、依性別分組（同組同性別）、各組盡量男女均衡。現況性別依「女生起始座號」推算；新增學生性別欄位可明確覆寫此預設，未提供且無法由現有設定判定者視為未指定。選擇性別策略時，對未指定學生提示處理方式，不自行猜測。
- 抽組結果可先產生草稿，再逐組手動移動學生、交換組員、改組名；允許鎖定已安排的組別／學生後只重抽未鎖定部分。提供復原／重做。
- 任務可選擇「只分組」或「同時安排座位」。同時安排時，每組可指定桌組／座位區；老師可預先指定，再抽未安排者，最後手動調整。容量不足時提供可行分組與未安排名單，不丟棄學生。
- 任務名稱、建立時間、名單快照、分組規則、隨機結果、手動變更及座位分配作為獨立活動紀錄保存、匯出與重新開啟。不得改寫日常座位抽籤結果。

## 建議資料模型

在 v1 之上引入版本遷移；概念上區分班級設定、名冊、空間版型、日常座位結果和活動工作階段：

```text
state
  version
  roster: [{ number, name, gender, fields, requiresSeat, participatesInActivities }]
  room: { mode, dimensions?, tables: [{ id, type, x, y, rotation, seats: [...] }], paths: [...] }
  seatingPlan: { assignments, manualDraft }
  activities: [{ id, title, rosterSnapshot, groupingRule, groups, seatAssignments, history }]
```

實作時可沿用目前學生資料解析器和現有 assignment，但需避免把名冊學生數直接當作實體座位需求。`requiresSeat` 預設 true；`participatesInActivities` 預設 true，兩者語意分開。

## 分階段實作

### Phase 0：規格與相容性基礎

- 固定名冊中座號、性別與自訂欄位的權威來源；明確定義性別欄覆寫「女生起始座號」推算的優先序，並定義無座位學生是否仍屬於抽組名單（建議預設是）。
- 擬定 v1→v2 JSON/localStorage 遷移、重複座號、刪除學生、容量不足和舊版匯入行為。
- 盤點目前每個流程對 `buildStudents()` 的假設，抽出 `rosterStudents`、`seatRequiredStudents`、`activityStudents` 三種查詢。

### Phase 1：不需實體座位

- 新增學生座位需求欄位和手動排位名單操作。
- 更新驗證、抽座位、預排、手動草稿正規化、完成展示、旋轉及匯入匯出。
- 展示畫面可選擇是否列出「不需實體座位」名單；預設管理模式可見、正式座位圖不占位置。
- 完成後即能解決名單比實體座位多但仍需存檔的核心痛點。

### Phase 2：任務分組 MVP

- 新增任務工作區、2–6 人目標組大小、全班公平抽組、三種性別策略、手動調整、鎖定與復原。
- 先只輸出分組清單和活動紀錄；任務結果與日常座位計畫分離。
- 支援匯出可列印／分享的分組結果，活動記錄隨 JSON 備份。

### Phase 3：桌組空間編輯器

- 新增自由配置畫布、桌型、座位 ID、拖移／旋轉／縮放、通道標示、撤銷重做與手機觸控操作。
- 提供常見模板：矩形網格、小組桌、圓桌、U 型；可從現有網格轉換並保留有效座位與學生配置。
- 讓日常座位、任務組別及座位分派共用同一套空間 seat ID。

### Phase 4：任務分組與桌位整合

- 任務組別指派至一張桌或指定座位區；支援預先安排、抽取剩餘學生、手動調整與容量檢查。
- 支援同一活動重新抽組、複製任務、保存版本及回看結果；不影響固定日常排位。

## 驗收條件

- 舊 v1 JSON 和既有 localStorage 可載入；未標示學生一律保留需座位，舊有結果不被意外清空。
- 全部學生名冊可完整保留，即使需要座位的人數大於座位數；明確標記不需實體座位後，手動模式可完成並匯出。
- 所有需座位學生恰好占一席；不需座位者不會出現在任何座位 assignment；走道無法排人。
- 2–6 人分組涵蓋所選名單且不重複、不遺漏；可選男女策略；手動預排與調整後可保存、重載及復原。
- 圓桌、U 型、小組桌的座位可個別指定；通道區域不生成座位，版型存檔及載入後位置一致。
- 任務分組及任務座位配置不改動日常座位結果；JSON 匯入匯出、舊網格旋轉、響應式版面及鍵盤操作均有覆蓋。

## 測試與風險

- 擴增無依賴 Node 測試：資料遷移、座位需求統計、分組分布、性別策略、鎖定後重抽、容量邊界、重複／缺席名單、序列化往返。
- 擴增瀏覽器操作驗證：無座位標記和完成、桌組拖放／旋轉、觸控／鍵盤、分組預排與調整、儲存重載、舊檔匯入。
- 主要風險是 `students.length` 同時代表名冊及需座位人數的隱含假設散布在引擎、手排和容量提示；Phase 1 要先集中拆分，避免局部修補造成座位遺漏。
- 自由配置會大幅增加幾何、響應式及操作複雜度；需優先完成鍵盤替代操作、觸控命中區與復原流程，再把桌組與分組整合。
- 本計畫是程式碼與既有文件盤點後的產品／工程提案，尚未做教師訪談或現場走道可用性驗證。建議在 Phase 1 原型後找教師試用，在 Phase 3 以教室平面案例檢查辨識度與輪椅動線表達。

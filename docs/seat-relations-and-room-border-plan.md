# 手動編輯後的座位關係與教室邊框修正計畫

日期：2026-11-08。範圍：研究目前工作目錄版本，提出修正設計；本文件不代表功能已完成。

## 1. 研究結論

建議保留桌椅自由移動，增加由目前位置推導的「邏輯棋盤」，並統一座位關係更新流程。棋盤負責橫排／直行／棋盤交錯，鄰接圖負責同儕不相鄰，桌組歸屬負責不同桌。三者不能互相取代。

教室形狀延用現有矩形寬高模型與八個控制點，補上圖中邊框可直接選取的入口及就地比例工具。首期不擴充為任意多邊形。

## 2. 已確認的問題與仍需驗證的部分

| 發現 | 程式依據／驗證 | 影響 |
| --- | --- | --- |
| 男女交錯仍讀舊行列 | `seat-engine.js` 的 `genderPatternParity()` 只讀 `seat.row/col`；`drawing-scene.js` 的 `setBox()` 不更新行列 | 拖曳後仍按原座位編號分色，與畫面脫節 |
| 新增自由座位沒有空間行列 | `drawing-scene.js` 的 `nextSeat()` 使用 `row:0,col:state.seats.length` | 新增座位的橫排模式可能全部落在同一列判定 |
| v3 畫布漏更新快速配置按鈕 | `ui.js` 的 `renderSeatGrid()` 在 v3 分支直接返回，未走後面的按鈕顯示設定 | 可能延續先前版型的按鈕狀態；桌組與獨立座位混合時尤其不明確 |
| 完成編輯其實已有重算 | `app.js` 的 `finishLayoutDraft()` 呼叫 `layoutPlanner.prepare()`，後者重建 `seatTopology` 並求解 | 不能把同儕分開問題直接判定為「完成時沒有重算」 |
| 手動鄰接結果會被覆蓋 | `separation-ui.js` 可保存人工增刪連線；`layout-planner.js` 完成時無條件改用 `drawingScene.edges()` | 老師明確修正的關係，可能在下次完成後消失 |
| 同儕鄰接演算法只有幾何啟發式 | `drawing-scene.js` 的 `edges()` 使用主方向、間距中位數及八方向最近點，沒有使用通道阻隔 | 不規則、稀疏、混合桌型的判定可能與老師認知不同，需具體案例驗證 |
| 拖動椅子可能改變桌組 | `drawing-objects.js` 的 `up()` 在移動單椅後依落點呼叫 `reparentSeat()` | 同桌規則可能因移動而改變；這是現有行為，是否符合教師期待需調整 |
| 外框選取入口漏接 | `drawing-objects.js` 的 `hit()` 只辨識標記與 `data-drawing-kind`；未辨識實際教室邊界 | 工具列可選教室形狀，但直接點邊框會被當成空白框選 |
| 鄰接預覽未隨座標尺度調整 | `separation-ui.js` 的 SVG 已動態計算 viewBox，但圓點與字級仍固定為 1.5／2.5 | v3 採數百到數千的教室座標，預覽的點、文字與線可能難以辨認 |

已執行 `node tests/drawing-scene.test.js`、`node tests/seating-constraints.test.js`，兩者通過。另以 Node VM 載入現有模組，將 2×2 教室的座位上下移動：`rows` 套用前後的座位類型完全相同；同一布局經 `layoutPlanner.prepare()` 回傳 `solved`，且拓撲為 confirmed。這證明舊行列問題，也證明基本完成流程有重算。

尚未重現教師實際操作中的所有「同儕分開失效」路徑；目前證據支持上列覆蓋、歸屬與推導問題，不能宣稱已找到唯一根因。後續瀏覽器測試須涵蓋編輯完成、修改規則、重新抽位與重開檔案的完整順序。

## 3. 座位資料設計：自由位置加邏輯棋盤

### 3.1 明確分開四種資料

- **實際位置**：沿用 `drawingScene.objects(state)`，取得轉換後的教室座標。它是空間計算唯一入口，禁止各功能另算一套百分比或螢幕像素。
- **邏輯棋盤**：以座位 ID 對應推導的行、列、區塊與方向；不改寫舊 `seat.row/col`，避免破壞相容、標籤與既有識別用途。
- **鄰接圖**：記錄哪些座位視為相鄰；同儕不相鄰仍預設包含斜角，維持既有規則。
- **桌組歸屬**：沿用穩定 table ID；移動位置與轉移桌組是兩個不同操作。

建議新增 `js/seat-spatial-model.js`，提供 `derive(state)` 與 `ensureCurrent(state)`，集中回傳 `positions`、`logicalCells`、`edges`、`tableBySeat`、`warnings` 及版本簽章。所有結果均以穩定 seat ID 索引，不能以陣列順序當座位身分。

### 3.2 棋盤如何推導

1. 使用教室共同座標，明確保存排列方向。原網格首次轉換時保留已知間距與方向；整間旋轉時同步旋轉方向。自由布局可提供「以目前畫面橫直方向」重新辨識，避免微小移動使自動主軸突然翻轉。
2. 以典型座位中心間距建立虛擬格，投影後容許小幅偏移；保留空格與通道，不把左右有空隙的兩群座位直接壓成連號。不要只按 y 或 x 排序取序號。
3. 遠離原排列的孤立席、圓桌、U 型及不同方向桌組，分區處理；混合區域保留獨立棋盤或使用桌邊順序。
4. 容差以典型中心間距為基準設定並經案例調整，不採固定螢幕像素。接近分界時保留前一次歸類的緩衝區，減少小移動造成跳列。
5. 同一格出現兩席、間距不足以推導或單一區塊無法形成橫直排列時，顯示具體座位提示；不可把缺少資料默認為第 0 格。

「吸附格線」可供選用，協助排整齊；預設不強制吸附。使用者不需要為了計算而犧牲自由定位。

### 3.3 男女快速配置

橫排、直行與棋盤模式改讀 `logicalCells`；桌組模式依桌面局部座標判斷桌邊／環狀順序，並處理獨立席，不能漏掉無桌組座位。v3 每次渲染都要重新設定可用按鈕與說明，禁止沿用上一次版型狀態。

棋盤交錯指上下左右交錯，斜角可能同性；同儕不相鄰則可包含斜角。不能將男女交錯定義為「鄰接圖上所有邊都必須異性」，因為八方向鄰接會有三角形，兩種性別無法讓所有邊都交錯；奇數圓桌也無法首尾全部交錯。

保留目前男女數量不均時放寬部分座位的能力，但套用前預覽「限定男／女／不限」數量及受影響預排。既有預排不能因計算方便默默清掉。`genderPlan` 必須記錄來源：教師選擇的明確配置與自動平衡偏好分開，完成教室時不能無條件以 `balanced` 覆寫教師選擇。

### 3.4 同儕分開

規整區域使用棋盤八方向候選，再以實際距離、空格及阻隔區檢查；自由區域使用幾何鄰接，限制極遠座位連線，避免某席因「總得找最近的人」而跨越整間教室連線。

通道需有明確語意：一般留白不自動解除分開規則；通道可標記「此通道兩側不視為相鄰」，只在啟用時移除跨越該通道的連線，並在預覽呈現理由。不同桌組與不相鄰仍是獨立條件，不能假設不同桌一定不相鄰。

人工修正另存為 `adjacencyOverrides: { add, remove }`，實際圖為「自動圖 + 人工新增 − 人工移除」。重新推導不覆寫修正；座位刪除後清除失效端點並通知。移動後保留以 ID 指定的修正，但把受移動影響的修正標為待檢查，讓老師能復核或重設為自動。舊資料中只有完整人工圖、無法辨識哪些邊曾修改時，先保留舊確認圖並標示來源，提供重新辨識，不猜測後直接覆蓋。

單椅拖曳預設保留桌組歸屬。需轉移時，以「移到此桌／改為獨立席」操作或明確落點預覽提交；將椅子移遠也提示歸屬，避免不同桌規則在無感操作下改變。

## 4. 共用更新流程

```text
拖曳預覽 → 放開提交幾何 → 標記空間模型過期
                         ↓
       推導棋盤、桌組與自動鄰接 → 合併人工修正
                         ↓
       驗證預排、性別配置及分開規則 → 保存同一版結果
```

完成編輯、套用快速配置、修改分開規則、抽位、手動交換與載入檔案都使用共同的 `ensureCurrent()`。拖曳中只做必要預覽；放開後刷新，避免每個 pointermove 都完整求解。變更名單與性別條件只重做配置驗證，不重推幾何。

分開記錄空間與規則簽章。空間簽章只涵蓋影響座位位置、尺寸、排列方向、桌組歸屬及阻隔的資料；縮放、選取、門的名稱等不應觸發重算。純平移與整間旋轉可保留關係，但邏輯方向需依操作語意同步更新。移動黑板本身不自動改變排列方向。

計算使用快照，提交時核對版本；途中又被修改就取消舊結果。幾何錯誤、規則互相矛盾、逾時與拓撲待復核分別顯示，不統稱「失效」。有硬性分開規則時不得退回不受限隨機排位；自動男女平衡是偏好，教師指定的座位性別才是硬條件。

保留目前完成教室的草稿／正式資料交易流程與失敗恢復。已完成排位若仍符合新位置及規則就保留；否則保留可恢復草稿、指出衝突，不把不合規結果呈現為完成。

## 5. 教室形狀：直接在圖上操作

### 5.1 圖上配置

```text
工具列：[選取] [桌椅] [標記] [教室形狀] [復原] [完成編輯]

          教室形狀  寬：高 4:3
       ■─────────■─────────■
       │        黑板        │
       │                    │
       ■   □ □ □   □ □ □   ■  ← 點牆線即可選取外框
       │   □ □ □   □ □ □   │
       │                 門 │
       ■─────────■─────────■

       [4:3] [16:9] [1:1] [3:4] [鎖定比例]
       寬 [1200] ：高 [900] [套用]
```

只在編輯模式啟用。點教室任一邊框選取 `bounds`，立即出現八個控制點與就地工具；不必先到側欄選教室形狀。一般預覽與展示維持既有操作。

### 5.2 命中與互動設計

- 在教室四條真實邊界上提供透明點擊帶，尺寸以螢幕像素設定，滑鼠約 10–12px、觸控約 24px，縮放後仍可點。可用四條獨立 DOM 命中帶或相機反算後的邊界距離，不以整個教室背景攔截事件。
- 命中優先序：已顯示控制點、桌椅／門等物件、牆線、內部空白。貼牆物件優先，並保留「教室形狀」按鈕供牆線被遮住時選取。
- 點牆只選取，不立即移動或縮放；放開後控制點持續顯示。空白點擊／Esc 取消；內部空白拖曳繼續供框選；空白鍵／中鍵／平移工具繼續平移。
- 外框可鍵盤聚焦，Enter／Space 選取；提供寬高輸入與比例鎖定，不能只有無文字的把手。控制點配合游標方向，尺寸以螢幕像素維持可用下限。
- 拖左右邊調寬、上下邊調高，四角可同時改尺寸。沿用現有中心基準縮放語意，並在圖上顯示預覽；若未來改成固定對邊，需另定義教室原點與物件補償，不能只改把手公式。
- 拖曳中的相機維持穩定，放開後不自動縮放導致外框跳動。pointercancel、失去捕捉或 Esc 恢復；一次拖曳只建立一筆復原。
- 縮小外框時保留桌椅尺寸，不擠扁物件。超界位置以紅框與「定位問題／等比放入／復原」處理；超界不能直接完成。放大或改視圖縮放不能改座位關係。

實作沿用 `drawingObjects` 的 bounds 選取與 overlay，擴充 `hit()/down()`；`classroom-editor.js` 負責命中帶及相機整合，`assets/styles.css` 負責可點區與控制點。避免另外建立一套互相獨立的外框拖曳器。

## 6. 實作順序與資料相容

| 階段 | 主要檔案 | 交付與完成條件 |
| --- | --- | --- |
| 1. 固定重現案例 | `tests/drawing-scene.test.js`、瀏覽器測試 | 覆蓋移動後快速配置錯誤、人工鄰接被覆蓋、單椅歸屬與點外框失敗 |
| 2. 空間模型與更新入口 | 新增 `seat-spatial-model.js`；調整 `seating-constraints.js`、`layout-planner.js` | 所有入口使用同一份目前位置；保留人工修正，失敗不提交 |
| 3. 男女配置與同儕規則整合 | `seat-engine.js`、`app.js`、`ui.js`、`constrained-arranger.js`、`separation-ui.js` | 快速配置符合新位置；明確配置不被偏好覆寫；預覽可辨識且驗證／求解一致 |
| 4. 圖上教室形狀 | `drawing-objects.js`、`classroom-editor.js`、`assets/styles.css` | 四邊可選、八點可拖；桌面／手機、縮放／平移後命中正確 |
| 5. 持久化與回歸 | `storage.js`、`class-data.js`、`app.js`、既有測試 | 覆核新欄位在正規化、匯入驗證、班級紀錄、複製、草稿及復原的保存 |

目前 v3 場景已會以完整檔案版本 7 儲存。推導快取可在載入時重建；人工修正、排列方向與教師選擇是意圖資料，需持久化。新增欄位應有局部 schema/version；是否提升完整檔案版本須依舊版讀取器會否丟棄重要意圖判定。不可只在目前記憶體生效。

舊 `seat.row/col` 與 seat ID 不改動；既有無新欄位的檔案可載入。新欄位驗證包括重複邊、自連線、不存在端點、非有限數值及過大資料量。研究時工作樹已有大量修改與未追蹤檔，實作應在現況上做針對性修改，不能重設或覆蓋既有成果。

## 7. 驗收案例

1. 4×6 網格轉自由編輯，交換兩個跨行座位的位置；完成後套用橫排／直行／棋盤，結果依目前圖上位置，ID 與學生身分不改。
2. 新增、刪除、複製獨立席及混合桌組，所有可用席都有明確配置結果；沒有因缺少 roomOrder 而全部視為 index 0。
3. 輕微錯位不跳行；明顯跨行會更新；留空格與通道不被自動壓縮。無法辨識時有預覽與調整方式。
4. 圓桌奇數席、U 型及兩種方向的桌組可用明確順序配置；不承諾無法達成的全邊異性交錯。
5. 將一對須分開學生所在座位拉近／拉遠後，完成、抽位及手動交換都使用同一張新圖，不能仍以舊位置判定。
6. 人工新增／移除鄰接線後，再進入並完成編輯、存檔重開，修正仍在；座位刪除或移動時有相應清理／復核提示。
7. 單椅拖到桌外不默默變成不同桌；明確轉桌後，同桌規則即時更新。斜角不相鄰與棋盤同性斜角可同時正確解釋。
8. 改變縮放、平移、移動門或黑板不使拓撲失效；整間旋轉四次後位置與關係恢復。
9. 在 50%、100%、200% 檢視倍率及手機上，點四邊均可選外框，八控制點能操作；貼牆門仍可選，內部框選與平移仍正常。
10. 改外框比例、拖曳取消、復原／重做、超界修正及完成，沒有物件變形、座位遺失或指標偏移。
11. 男女人數不均、固定座位及多個分開條件無解時，清楚說明衝突；取消／逾時保留草稿，禁止產出違反硬性規則的結果。
12. 切班、班級紀錄、複製、完整備份匯入匯出後結果一致；展示隱藏所有關係連線、教師規則與編輯控制點。

實作完成後執行相關 Node 測試與上述瀏覽器整合案例，再執行 `tests/run-tests.py --browser` 的既有回歸。此次僅執行第 2 節記載的兩個測試及局部重現，尚未執行完整瀏覽器回歸。

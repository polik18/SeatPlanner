# SeatPlanner Inclusive：班級紀錄與同儕分開安排修訂計畫

狀態：研究與規劃，尚未實作。研究基線：Inclusive 2.0，Git `a126160`。本次不修改應用程式、不改現有班級資料、不重新發布或替換 2.0 交付包。

本次要求優先於原計畫中只靠自動暫存及固定座位的做法。第一項暫以「老師可以明確儲存、重新開啟、備份及延續使用班級」解讀；班級教學日誌若也需要，另列延伸需求，不把目前空白觀察表宣稱為已可保存的班級紀錄。

## 1. 研究結果與缺口

| 現有位置 | 已有能力 | 缺少的能力 |
|---|---|---|
| `app.js` 班級管理 | 新增、複製、切換、刪班 | 明確的儲存班級、開啟紀錄、學期整理、封存、排位版本列表 |
| `storage.js` | 瀏覽器 localStorage 暫存、v1–v4 匯入、全工作區備份 | 單班完整檔案、持久版本紀錄、穩定跨匯入身分與衝突選擇 |
| `preserveRecovery()`／桌位 undo | 本次頁面的復原 | 關閉後仍能選取的歷次班級／排位版本 |
| `student-draw.js` | 以班名與名單簽章保存目前一輪 | 獨立的每班抽選紀錄；目前切換不同班級可能覆寫唯一儲存槽，且不包含於班級 JSON |
| `seat-engine.js:arrange()` | 容量、性別座位、固定預排後洗牌 | 任意學生配對的分開安排、相鄰定義、限制求解 |
| `manual-seating.js`、結果交換 | 教師可自由放置與交換 | 新增硬性配對規則後的共同檢查與阻擋 |
| `app.js:enterPresentation()` | 既有展示流程 | 目前手排結果可直接視為有效；新硬性規則不能沿用此捷徑 |

研究另以 Node VM 讀取現有模組：在四席一列中把 1、2 號放相鄰，現有驗證仍回傳 valid=true；目前沒有配對規則，這是功能缺口而非既有測試承諾失效。`serializableState()` 亦未包含任何配對規則欄位，不能只加畫面或臨時記憶體設定。

## 2. 需求 A：真正可延續使用的班級紀錄

### 2.1 老師看得到的操作

增加「我的班級」入口與「儲存班級」主按鈕。班級卡列出班名、學年度／學期（選填）、學生數、最近儲存時間、最近一次排位紀錄及草稿狀態。

| 操作 | 預定行為 |
|---|---|
| 建立班級 | 填班名、貼名單、選填學期；建立獨立班級身分 |
| 儲存班級 | 建立可重開的具名紀錄，例如「11 月座位」；沒修改時不重複建立同內容版本 |
| 繼續編輯 | 接續此班最新暫存草稿，與開啟已保存版本明確區分 |
| 開啟紀錄 | 預覽版本時間、名單、教室及規則摘要；確認後還原一致的整份版本，先保留目前草稿 |
| 備份此班 | 下載單班完整 JSON，包含名單、教室、規則、結果、草稿、活動與班級紀錄 |
| 備份所有班級 | 保留現有全工作區備份；不與去敏分享檔混用 |
| 開啟班級檔 | 驗證後預覽；同一穩定班級 ID 可選更新原班或另建副本，更新前保留舊版 |
| 複製／封存／刪除 | 複製時讓老師選只複製教室，或連名單及規則；封存不刪資料；刪除需確認且可復原 |

「紀錄」是資料快照，不是畫面截圖。至少保存名單、座位、固定預排、同儕限制、手排草稿、最近結果、分組活動；抽學生目前輪次也改為隨班保存，補足目前完整班級備份的缺口。

### 2.2 暫存、儲存與備份要說清楚

- 自動暫存：保護進行中的修改；不能冒充老師已建立的具名班級紀錄。
- 儲存班級：建立有時間及名稱的版本；可重開。規劃尚有衝突也可保存為「未完成規劃」，不能標示排位完成。
- 備份檔：可帶到其他裝置或瀏覽器重新開啟。下載不等於應用已獲得自動寫回該檔案的能力。
- 顯示「草稿已暫存」「班級紀錄已儲存」「尚未備份到檔案」「儲存失敗」等不同狀態，只在成功寫入後顯示儲存成功。
- 本機保存限此裝置與瀏覽器，清除資料、無痕或儲存拒絕可能使紀錄無法保留；仍提供明確的單班檔案路徑，不承諾永久保存或雲端同步。
- 具名版本先由老師管理，不默默輪替刪除；容量不足顯示大小／受影響項目，提供下載備份與選擇清理，不自動清空。

### 2.3 班級與學生身分

班級使用永久 UUID，不再以 `class-1` 或班名判斷是不是同一班。班名可修改，班級 ID 不變。紀錄的時間、學期、版本中繼資料與業務 state 分開。

學生增加穩定身分對照 `rosterIdentity: [{studentId, number}]`；姓名與其他現有資料仍由現有名單解析，不另造第二份可互相覆寫的名單。限制使用 studentId，排位引擎在邊界轉成現有座號運算。

修改座號／重新貼名單時，先顯示「原學生更正／改號」與「換成新學生」的對照；禁止僅憑同名、相同座號就把舊限制套給新學生。刪除／轉出學生後，歷史版本保留原身分，當前相關規則顯示停用原因，由老師確認。複製教室給另一班預設不複製學生及配對規則。

## 3. 需求 B：事先規劃誰與誰分開安排

### 3.1 教師操作

「優先安排」改為可清楚選擇兩類任務：

1. 保留位置：沿用選學生、指定座位。
2. 同儕分開安排：搜尋／選學生 A、學生 B，選關係，預覽教室中的限制範圍，再儲存規則。

教師頁可新增、修改、停用、刪除多項規則；A–B 與 B–A 視為同一配對，同一學生不能選兩次。列出規則數、啟用狀態、是否與固定位置或目前結果衝突。支援同一學生與多位學生分開安排。

名稱採中性的「分開安排／同儕座位規則」，不公開「問題學生」等標籤，不要求填醫療或安排理由。規則屬教師設定，投影與去敏分享一律不帶出。

### 3.2 「不能坐在一起」必須有明確範圍

| 規則 | 建議定義 | 備註 |
|---|---|---|
| 不相鄰 | 網格預設包含左右、前後及斜前後，共八方向 | 介面先畫出範圍，不只用一句模糊的「坐一起」 |
| 不同桌組 | 圓桌、島型或其他自由布局中的不同桌組 ID | 可與不相鄰並用；不同桌不自動代表距離遠 |
| 個別座位鄰接調整 | 教師在自由教室確認哪些座位算相鄰 | 補足對坐、跨桌近距離、特殊走道等情況 |

網格的相鄰採 `max(abs(rowA-rowB), abs(colA-colB)) = 1`；走道沒有可坐頂點，不把隔著整欄走道的座位重新壓縮成相鄰。示範：一列三席，1、2 號分別坐兩端，中間坐其他學生或留空，即符合不相鄰。

自由布局不能依座位 ID、陣列順序或畫面螢幕像素距離猜測相鄰。規劃可預覽、可修正的座位鄰接圖，圖的邊代表「視為相鄰」，依教室邏輯座標生成建議並由教師確認；縮放或改裝置不改規則。圓桌要包含首尾相鄰，對坐是否限制由圖與選項明確表示。

自由布局首次使用「不相鄰」或更動桌型、座位、位置後，若無可信任的已確認鄰接圖，就阻擋使用這項規則抽位並引導確認；不能假裝所有座位都不相鄰。「不同桌組」可以直接依有效桌組資料檢查。

單一 U 型大桌若選「不同桌組」可能無解，應明確建議改用已確認的鄰接規則或增加桌組；不自動放寬。網格規則切換自由布局時，也需確認語意，不偷偷改成另一種規則。

### 3.3 適用與不適用範圍

- 本次是日常座位的硬性限制：抽籤、重抽、固定預排、手排完成、結果交換、復原後展示、匯入結果、布局變更後均要檢查。
- 既有手排可不採用性別／固定位置限制的政策，不能成為略過新配對硬限制的理由。手排過程可暫存未完成草稿，但完成／展示前必須通過；交換造成新衝突時整次拒絕。
- 不需實體座位的學生，其相關座位配對目前不參與求解；規則保留並顯示原因。改回需座位時重新檢查，不能沿用舊有效狀態。
- 本次不自動限制「課堂任務分組」或抽學生名單；不能坐附近與不能同組是不同需求。未來如需要，可另增活動範圍選項。
- 不新增「必須同坐」等未要求的配對規則，以免增加教師負擔與求解衝突。

## 4. 求解與共用驗證設計

### 4.1 絕對不能只加隨機重抽迴圈

無新規則時保留原抽位流程；有啟用規則時，改用受限制的隨機求解：

1. 建立不可變的名單、可用座位、固定位置、桌組／鄰接圖及規則快照。
2. 檢查容量、重複身分、固定位置衝突、無效座位及未確認的自由布局鄰接圖。
3. 先固定合法預排，建立其餘學生的候選座位，沿用現有性別座位條件。
4. 使用回溯搜尋，優先處理候選座位較少／限制較多的學生；分配後立即排除衝突候選，提早回溯。
5. 對同順位學生與候選座位隨機排序，保留多次抽位的變化。不宣稱對所有合法排位為均勻抽樣。
6. 候選解必須再由獨立驗證器逐條檢查，並確認當前名單、布局與規則版本未改變，才可揭曉及保存。

計算需可取消、分段讓出畫面，避免鎖住手機；不強制依賴可能影響 file:// 的 Worker 部署。時間／節點預算在原型效能測試後確定，不承諾任意規則量皆能即時完成。

| 求解結果 | UI 行為 |
|---|---|
| 成功 | 全部啟用硬限制通過後才揭曉及提交 |
| 已證明無解 | 僅在完整搜尋或可證明的先驗衝突後顯示；列出可定位的衝突，不承諾最小衝突集合 |
| 時限／節點預算用完 | 顯示「尚未找到符合結果，可繼續或調整規則」，不能誤報已證明無解 |
| 取消／條件變動 | 保留先前結果與草稿，丟棄未完成候選解 |

固定預排已使 A、B 相鄰時，不移動固定位置、不偷刪規則、不揭曉錯誤排位，先讓教師處理衝突。規則太多也不能暗中放寬。

### 4.2 共用驗證入口

新增 `validateAssignment(state, assignment, options)`，負責座號完整性、重複、有效座位、配對、桌組及鄰接檢查。草稿可用 partial 模式呈現衝突；所有完成／公開結果使用完整檢查。舊性別／固定限制仍依既有手排政策處理，新配對硬限制一律適用。

抽位、手排、交換、預排、旋轉、搬動自由座位、還原歷史、匯入、展示呼叫同一入口；禁止手排來源直接回傳 valid=true 的捷徑。

新增規則後若舊結果違反，保留舊結果為歷史，工作區顯示「舊結果與新規則不符，請重新編排」。不能把該結果標成已通過新規則，也不能在未檢查下展示。教師如需變更規則，必須明確修改／停用並重新驗證；不提供暗中忽略限制的按鈕。

布局與規則維護各自 revision。僅畫面縮放、語言切換不改拓樸；座位改號、移動或桌組改變需更新或重新確認。整間教室的剛體旋轉若能證明鄰接保持，可連同座位映射保留；否則標示待確認。

## 5. 資料版本與相容性

### 5.1 建議正式升為資料 schema v5

這次不只是 UI 欄位：舊 v4 程式不理解配對規則，且現有序列化／hydration 會丟失未知欄位。把限制硬塞進 v4 會造成「看似備份成功，重新開啟卻不再受限制」。因此建議新增 v5，而非讓 v4 備份暗中帶不保證的規則。

- 新工作區鍵：`classroom-seat-master:v5`。首次遷移前保全 v1–v4 原值，確認 v5 成功寫入才切換；不覆寫舊鍵。
- 有 v5 但損壞時停止覆寫，不偷偷回退 v4 造成舊資料看似覆蓋新工作。
- v1–v4 仍可讀入，補穩定 ID、空配對規則與明確標示的舊版基線紀錄；不虛構過去的儲存時間與歷史。
- v5 完整備份含規則、拓樸確認、學生身分與班級紀錄；單班／全班有清楚格式標記，整批驗證後才異動。
- 不提供會無聲丟規則的「相容 v4 完整備份」。舊版程式不能保證讀取 v5；去敏分享檔也不冒充可恢復的班級檔。
- 先保留 localStorage 架構，利用單一工作區值的寫入結果提交；版本快照不遞迴包含版本列表。以實際班級數／歷史容量測試決定是否需後續改 IndexedDB，不先引入伺服器或雲端。
- 教學 metadata 仍獨立。自動補 ID 或自動遷移不算新手真實活動。

建議結構（欄位名在實作前定稿）：

```text
workspace v5
  activeClassId
  classes[]
    id: 永久 UUID
    meta: 學年度、學期、建立時間、更新時間、封存時間
    state
      config / seats / assignment / manualDraft / activities / roomLayout
      rosterIdentity[]: studentId ↔ number
      seatingConstraints: version、配對、啟用狀態
      seatTopology: 定義模式、layoutRevision、已確認鄰接邊
      studentDrawRound: 此班抽選輪次
    records[]: id、名稱、savedAt、內容 hash、state 快照
```

規則配對例：`{id, studentAId, studentBId, relations: ['notAdjacent'], enabled: true}`。同一對可同時設不相鄰及不同桌組；不保存診斷或預設理由。

### 5.2 跨班與隱私

限制只屬該班；班級切換、封存與重開不串班。完整教師備份保留規則，去敏分享剔除配對、學生 UUID、保留標記及紀錄。展示 DOM、學生卡、列印座位表不包含規則及安排理由。規則列表不出現在學生端。

若未來加入班級日誌，需另定日期、活動、觀察、修改／刪除、保存期限、匯出及展示隔離；目前原計畫禁止將正式敏感教學紀錄直接存入此工具的邊界，不能因本次需求而默默取消。

## 6. 實作順序與出口條件

| 階段 | 工作／主要檔案 | 必須先通過 |
|---|---|---|
| R0：規格與失敗案例 | 班級紀錄流程草稿、鄰接範圍圖、v4 fixtures、缺口測試 | 確認儲存／草稿／備份語意；失敗案例可重現；保全 2.0 |
| R1：資料基礎 | constants、storage、app、建議新增 class-library／roster-identity 模組 | v1–v5 遷移與 round-trip；穩定 ID、容量失敗不毀原資料；單班／全班匯入衝突可選 |
| R2：班級操作 | 我的班級、儲存／開啟／封存、版本預覽、抽選隨班 | 關閉重開可接續；具名版本與草稿分清；跨裝置以單班檔恢復 |
| R3：限制核心 | 建議新增 seating-constraints、seat-topology、constrained-arranger | 小案例對照窮舉、正確區分無解與逾時、成功解全數通過獨立驗證 |
| R4：教師規劃介面 | 優先安排、雙學生選擇、規則清單、衝突與鄰接預覽 | A–B/B–A 去重；固定位置衝突可定位；自由布局未確認不假成功 |
| R5：全流程與交付 | 手排、交換、展示、復原、匯入、歷史開啟、i18n、文件 | 所有結果入口不可繞過；舊功能回歸、隱私／離線及教師任務測試 |

## 7. 驗收案例（新增測試，非目前已通過）

| 類別 | 必測案例與預期 |
|---|---|
| 真正保存 | 儲存「601／11 月」→ 關閉瀏覽器 → 重開仍在；草稿與該版本能分別開啟 |
| 單班檔 | 匯出單班 → 在乾淨瀏覽器匯入 → 名單、規則、排位、草稿、活動及紀錄一致 |
| 跨班 | 同名但不同學期兩班、快速切班、改班名，名單／限制／抽選輪次不互相覆蓋 |
| 身分 | 改座號保留原學生規則；同座號換新學生不繼承；重名不自動合併 |
| 版本還原 | 先預覽目前／歷史的名單與規則差異；還原後整份版本一致，原草稿可找回 |
| 最小成功 | 一列三席、兩位限制不相鄰學生，可在兩端成功排位 |
| 最小無解 | 一列兩席、兩位學生禁止相鄰；明確無解，原結果不變 |
| 斜角與走道 | 八方向包含對角；跨整欄走道不壓縮成相鄰，與預覽圖一致 |

# 教室編輯畫面大小與文字比例改善計畫

狀態：已完成第一版實作與自動化驗證；教師首次使用試用仍待進行。操作說明見 [教室畫布編輯器](classroom-canvas-editor-guide.md)。

## 1. 問題判斷

這次不是單純把字體調小就能解決。上一版將「整張教室完整塞進畫面」當成編輯預設，卻讓文字、圖形與控制把手採不同縮放方式，造成教室很小、字相對很大，也很難抓到要編輯的物件。

已確認的程式原因：

| 位置 | 現有行為 | 影響 |
| --- | --- | --- |
| `js/classroom-editor.js` 的 `paint()` | 每次以可用寬度與「扣掉工具列後的高度」取最小值，再乘上 `zoom` | 長形教室或工具區較高時，畫布被縮得很小 |
| `paint()` 與 `render()` | 選取、提交拖曳、展開精確設定後，重新量測工具區高度並計算畫布大小 | 看似同一倍率，實際畫布比例卻變動，物件位置也可能在畫面上跳動 |
| `assets/styles.css` 的 `.canvas-marker > span:first-child` | 字級使用 `clamp(10px, 1vw, 14px)` | 字級跟視窗走，圖形縮小時文字不跟著縮小，容易超出標記 |
| `.geometry-enabled .seat-main strong` | 字級使用 `clamp(12px, 1.7vw, 26px)` | 座位縮小後，文字仍可能偏大、被裁切或塞滿卡片 |
| `.marker-controls` | 選取框最小 80×64 螢幕像素 | 小標記的操作框比物件大很多，視覺上容易誤以為物件尺寸不正確 |
| 編輯介面配置 | 桌面仍保留一般班級側欄，物件工具區又占多行 | 真正留給教室圖的空間不足 |

## 2. 預期使用感受

按「編輯教室」後，進入以畫布為主的大型工作區。老師先看清楚教室，點選物件就能拖拉；想看細節就放大、移動畫面。選取其他物件、開啟設定或拖動外框時，檢視倍率維持不變。

「看全圖」是明確按鈕；不在每次操作後自動把整張教室縮回去。

## 3. 介面配置

### 桌面與筆電

使用頁面內的全視窗編輯工作區，不要求瀏覽器授予全螢幕權限。進入時暫時收起一般班級側欄與頁首功能，退出時還原原畫面、捲動位置與焦點。

- 上方：一行主要工具，包含完成、復原、重做、選取、標記與外框。
- 中央：獨立畫布視窗，具有固定可用範圍，不因屬性面板內容增減而變高或變矮。
- 右側：固定寬度的物件屬性面板；未選取時顯示簡短提示，不把畫布區域收回或擴張。
- 底部角落：倍率、－、＋、看全圖、放大選取物件。

右側面板寬度先以 240–280px 試作；實際值依 1366×768 與 1280×720 的畫面驗證調整。主工具列目標為 48–56px 高，不再把完整說明與多組按鈕全部堆在畫布上方。

### 手機與窄螢幕

畫布保留主要空間，工具使用精簡列；屬性放在可收合的底部面板。面板展開可暫時覆蓋部分畫布，但不重新計算相機倍率。需要編輯細節時可收合面板、放大與平移。

工具保留文字名稱或可辨識的標籤，不只剩沒有說明的圖示。

## 4. 縮放與移動畫面的規則

### 固定相機，不在 `paint()` 內重新決定倍率

新增獨立的檢視狀態，例如 `camera = { scale, offsetX, offsetY }`，僅供目前編輯工作區使用。`paint()` 依此狀態呈現，不再從工具列高度推導物件大小。

初始化、看全圖、放大選取物件是三個明確動作：

1. **初次進入**：只做一次初始化。先計算全圖倍率；若物件已小到不利編輯，改用以教室中心為主的工作倍率，允許教室部分超出視窗，並顯示「可拖動畫面查看其他區域」提示。
2. **看全圖**：將整間教室連同操作邊距放入畫布視窗，接受物件可能較小，供檢查整體配置。
3. **放大選取物件**：置中並放大目前物件，保留控制把手與旋轉把手的操作空間，不讓物件填滿整個視窗。

初始可編輯門檻先以一般標記短邊約 24–32px 試作，並限制預設放大倍率；極小或刻意縮小的標記不強迫把整間教室放到過大，交由「放大選取物件」處理。這些數值是驗證起點，不當成所有教室都適用的固定答案。

- 縮放範圍先提供 10%–400%，顯示實際倍率。100% 定義為一個教室邏輯單位對應一個 CSS 像素，不宣稱等於實際尺寸。
- ＋／－以畫布中心縮放；滑鼠滾輪縮放以游標位置為中心，僅在畫布區攔截。
- 空白鍵加拖曳、滑鼠中鍵可平移；另提供「移動畫面」工具，避免只能靠快捷鍵。
- 觸控以雙指平移及縮放；單指在選取模式拖物件，在移動畫面模式拖畫布。
- 切換選取、展開屬性、旋轉或調整外框不改變相機倍率。
- 視窗尺寸改變時保留目前畫面中心與倍率；若目前處於使用者指定的「看全圖」模式，才重新適配。
- 調整外框大小不自動縮回全圖。外框超出畫布時可平移或按看全圖。

## 5. 圖形、文字與把手各自的縮放方式

| 元素 | 新規則 |
| --- | --- |
| 黑板、門、老師座位、座位與桌組 | 全部使用同一個教室座標與相機轉換 |
| 標記名稱、座號、姓名 | 與其所屬圖形同步縮放；移除編輯畫布中以 `vw` 決定字級的規則 |
| 選取輪廓 | 貼合真實物件外框，不再以 80×64 的放大矩形表示物件邊界 |
| 縮放與旋轉把手 | 外觀維持螢幕尺寸，不跟著圖形縮成小點；顯示於獨立的互動覆蓋層 |
| 工具列與屬性面板 | 維持一般介面字級，不受畫布縮放影響 |

文字基本字級定義在邏輯畫布中，例如標記 14 單位、座號 16 單位，實際大小由相機統一縮放。圖形縮小時，文字一起縮小，不能再因最小字級限制而擠爆物件。

縮到無法閱讀時，採「減少資訊」處理：低倍率只保留形狀與主要座號，隱藏次要說明；過小標記以停留提示、選取名稱與屬性面板補充。完整名稱與可及性名稱保留，不靠把文字放大蓋住圖形。

在編輯模式先降低座位圖中文字的干擾：編輯黑板、門、老師座位或外框時，座位維持可辨識的座號與輪廓；姓名與座位屬性說明視空間顯示。這只改編輯呈現，不變更既有學生顯示設定。

桌面把手外觀可維持約 10–12px、點擊範圍放大；觸控點擊範圍先以 40–44px 驗證。當物件太小、把手可能互相重疊時，減少顯示的把手並提供「放大選取物件」，不在同一點疊放八個可操作區。

## 6. 操作與資料的界線

必須明確區分：

- **看全圖、放大、縮小、平移**：只改檢視，不修改教室與標記資料，不加入資料復原紀錄。
- **改教室寬高、移動或縮放標記**：才修改幾何資料，沿用一次操作一筆復原。
- **等比適配內容**：會改變實際配置，移到屬性面板的進階操作，標明「調整配置」，不能和看全圖放在一起讓老師誤按。

沿用目前 v6 幾何資料，不因介面改版重新換算已儲存的物件。舊班級、預排、分開規則、班級紀錄與備份流程維持既有資料語意。

## 7. 技術實作範圍

1. `js/classroom-editor.js`：分離編輯工作區、相機與幾何變更；取消每次 `paint()` 自動適配的公式。
2. 新增共用座標轉換工具：`screenToWorld()`、`worldToScreen()`。拖移、縮放、旋轉、吸附與控制點皆使用同一組換算，包含平移量與畫布位置。
3. 統一內容渲染層：網格、自由桌型、標記及文字置於同一邏輯場景；外層只做一次平移與等比例縮放。避免 CSS `zoom`、百分比定位與另一套相機同時控制尺寸。
4. 獨立互動覆蓋層：依物件的世界座標計算把手螢幕位置，不用放大物件的選取框來換取點擊範圍。
5. `assets/styles.css`：新增大型工作區配置；編輯區移除 `vw` 字級與隨物件變小仍強制放大的字級下限，展示字級另保留。
6. `js/ui.js` 與 `js/app.js`：提供編輯專用呈現，完成後回到一般預覽；儲存、切班、展示與中斷操作的流程沿用並測試。
7. 編輯時使用移動工具拖畫面，不能誤觸座位交換或標記移動；多指手勢開始前，先取消未完成的單指物件拖曳。

## 8. 分階段執行

| 階段 | 交付 | 先確認的重點 |
| --- | --- | --- |
| A. 大型工作區與穩定倍率 | 收起一般側欄，工具與畫布分區，固定相機，提供看全圖與平移 | 選取物件、展開面板後，教室不再忽大忽小 |
| B. 統一文字與圖形比例 | 同一場景縮放，編輯標籤簡化，真實選取輪廓與獨立把手 | 黑板、門與老師座位的名稱不再擠爆物件 |
| C. 放大細節與觸控 | 放大選取物件、游標中心縮放、手機底部面板與雙指手勢 | 長形教室與小標記仍能容易操作 |
| D. 整合驗證 | 不同教室比例、螢幕尺寸、儲存與展示回歸 | 既有幾何與排位資料完整保留 |

先以 A+B 做出可實際比較的畫面，再完成 C+D；不以只縮小字級、加大幾個按鈕或調整一個固定高度結案。

## 9. 驗收條件

1. 以 1366×768、1280×720、1920×1080，以及 390×844 手機驗證；包含 4:3、16:9、3:4、狹長教室，網格與自由桌型皆測。
2. 同一物件在操作前後，僅切換選取、展開面板或點復原時，相機倍率不改變。若為復原幾何，只有預期的物件位置或大小改變。
3. 在 50%、100%、200% 三種倍率，標記圖形與文字的大小比例保持一致；工具列字級及把手可點性不受影響。
4. 小標記能透過放大選取物件後，清楚地移動、拉大、拉長與旋轉，控制區不互相遮擋。
5. 調整教室形狀時不自動縮回全圖；拖曳游標與操作點對準，不隨倍率或平移產生偏移。
6. 只縮放或平移畫面後，完整幾何序列化資料保持完全相同；不污染復原紀錄或造成班級草稿變更。
7. 既有班級重新載入、備份匯入、整間旋轉、預排、分開規則、取消拖曳與展示隔離測試仍通過。
8. 除自動化操作測試，必須保留改版前後相同班級、相同螢幕的截圖，檢查實際可用畫布面積、文字比例與把手重疊；不能只用「拖曳成功」判定易用性改善。
9. 以「把門移到另一面牆、拉長黑板、把教室改成較寬」作為教師試用任務，確認不需要先理解縮放數學或尋找多個設定面板。
